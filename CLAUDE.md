# CLAUDE.md — правила проекта «Сайт студии звукозаписи (Казань)»

Это обязательные правила для Claude Code. Следуй им во всех задачах проекта.
Если просьба пользователя противоречит разделу 2 («Юридические ограничения») — предупреди и предложи законный вариант.

## 1. О проекте
- Сайт-визитка студии звукозаписи в Казани + онлайн-запись по свободным слотам.
- Владелец — ООО (реквизиты подставляются в подвал). Аудитория — Россия. Язык — русский.
- Хостинг — российский виртуальный (shared) хостинг: PHP 8.x, SQLite, SSH/FTP, cron. Без Node.js в проде, без сборщиков и фреймворков.
- Бюджет минимальный: только бесплатные сервисы (Яндекс.Метрика, Yandex SmartCaptcha, виджет Яндекс.Карт/2ГИС).

## 2. Юридические ограничения (нарушать нельзя)

### 2.1. Локализация данных и запрет зарубежных сервисов (152-ФЗ)
- ЗАПРЕЩЕНО подключать: fonts.googleapis.com, fonts.gstatic.com, ajax.googleapis.com, maps.google.*, google-analytics.com, googletagmanager.com, reCAPTCHA, cdn.jsdelivr.net, unpkg.com, cdnjs.cloudflare.com, любые *.google.com, *.facebook.*, *.instagram.*, а также любые иные зарубежные CDN, шрифтовые/иконочные CDN, пиксели, счётчики и iframe-виджеты.
- РАЗРЕШЕНО: собственный домен; mc.yandex.ru (Метрика); api-maps.yandex.ru и *.maps.yandex.net (Яндекс.Карты) или виджет 2ГИС; smartcaptcha.yandexcloud.net (SmartCaptcha); api.telegram.org — только с бэкенда (сервер-сервер), никогда с фронтенда.
- Все шрифты — локальные .woff2 в /assets/fonts, только открытые лицензии с кириллицей (Inter, Montserrat, PT Sans и т.п.), субсеты кириллица+латиница. Иконки — inline SVG.
- Персональные данные клиентов (имя, телефон, комментарий) хранятся только в БД на этом сервере (РФ). Никаких выгрузок и синхронизаций в зарубежные сервисы.

### 2.2. Согласие и обязательные документы
- Форма записи содержит чекбокс, по умолчанию НЕ отмеченный: «Даю согласие на обработку персональных данных», со ссылками на /consent.html и /privacy.html. Без галочки отправка блокируется и на фронтенде, и на бэкенде. Вместе с заявкой сохраняются дата-время согласия и IP.
- Обязательные страницы: privacy.html (Политика обработки персональных данных), consent.html (текст согласия), rules.html (правила оказания услуг / оферта). Черновики генерируй с плейсхолдерами реквизитов и комментарием в начале файла: `<!-- ЧЕРНОВИК: ТРЕБУЕТ ПРОВЕРКИ ЮРИСТОМ -->`.
- Cookie-баннер при первом визите: краткий текст + кнопки «Принять» и «Отклонить». Яндекс.Метрика загружается ТОЛЬКО после нажатия «Принять». Выбор запоминается.
- Подвал каждой страницы: полное наименование ООО, ОГРН, ИНН, юридический адрес, телефон, e-mail, режим работы, ссылки на все документы. До получения реквизитов используй плейсхолдеры вида {{COMPANY_NAME}}, {{OGRN}}, {{INN}}, {{LEGAL_ADDRESS}}.

### 2.3. Язык (168-ФЗ, действует с 01.03.2026)
- Весь интерфейс, кнопки, заголовки и информация для клиентов — на русском языке.
- Латиница допустима только для зарегистрированного товарного знака (название студии) и как дублирующая надпись рядом с русской. Слова Booking / Sale / Price и подобные без русского эквивалента не использовать.

### 2.4. Прочее
- Никаких личных кабинетов и регистрации посетителей (иначе применяются требования 406-ФЗ о российских способах авторизации). Только форма заявки без аккаунта. Админка — служебная, для сотрудников.
- Не размещать ссылки и иконки Instagram и Facebook (Meta признана экстремистской организацией, её деятельность запрещена в РФ). Соцсети сайта: VK, Telegram, MAX, VK Видео/RuTube.
- Не использовать в текстах превосходную степень без подтверждения («лучшая студия», «№1», «самый…»).
- Фото людей и аудио в портфолио — только с подтверждёнными правами; перед добавлением спроси владельца о наличии согласий.

## 3. Архитектура
- Структура каталогов:
  - `public_html/` — корень сайта: index.html (или index.php), booking/ (страница записи), admin/, api/, assets/ (css, js, fonts, img), privacy.html, consent.html, rules.html, sitemap.xml, robots.txt, favicon.
  - `data/` — ВНЕ webroot: файл SQLite (bookings.db), логи, счётчики rate limit. Если хостинг не позволяет писать вне webroot — размести data/ внутри и закрой доступ через .htaccess (`Require all denied`).
  - Конфиг с секретами — файл .env (или config.local.php) вне webroot; в git не попадает (добавь в .gitignore). Обязательно приложи .env.example со всеми ключами и комментариями, где их взять.
- Бэкенд: чистый PHP 8.x, PDO + SQLite, prepared statements везде, единая точка подключения к БД.
- Фронтенд: семантический HTML5, один style.css, один main.js, без jQuery/React/сборщиков. Подход mobile-first.

## 4. Модуль онлайн-записи (слоты)
- Таблицы:
  - `slots(id, date, time_start, time_end, status)` — status: free | booked | closed.
  - `bookings(id, slot_id UNIQUE, name, phone, comment, consent_at, ip, status, created_at)` — status: new | confirmed | cancelled.
- Публичный API: `GET /api/slots.php?from=&to=` — свободные слоты на N дней вперёд; `POST /api/book.php` — создание брони.
- Бронирование выполняется в транзакции: слот занимается атомарно (UNIQUE-ограничение по slot_id + проверка статуса). При гонке — понятная ошибка «Этот слот только что заняли, выберите другой».
- Антиспам: серверная проверка SmartCaptcha (POST на https://smartcaptcha.yandexcloud.net/validate с секретным ключом), скрытое honeypot-поле, ограничение — не более 3 заявок с одного IP в час.
- Валидация: имя 2–60 символов; телефон нормализуется к формату +7XXXXXXXXXX; комментарий до 500 символов; весь вывод экранируется.
- Уведомления менеджеру о новой заявке, в порядке надёжности:
  1) E-mail через SMTP хостинга — ОСНОВНОЙ канал. Ошибка отправки логируется и повторяется, но не отменяет бронь.
  2) Telegram Bot API (sendMessage на chat_id менеджера) — ДОПОЛНИТЕЛЬНЫЙ канал: таймаут 5 секунд, любые ошибки перехватываются и пишутся в лог, бронирование при этом не ломается. Учитывай: api.telegram.org с серверов РФ периодически недоступен — код обязан переживать это молча.
- Клиенту после брони показывается подтверждение: «Заявка принята, менеджер свяжется с вами для подтверждения». Никаких автоматических SMS.

## 5. Админка (/admin)
- Вход по паролю: bcrypt-хэш хранится в конфиге, сессии, CSRF-токены на всех формах, задержка и лимит попыток при неверном пароле.
- Функции: генерация слотов на неделю вперёд по шаблону рабочего графика; закрыть/открыть отдельный слот; список заявок с фильтрами по дате и статусу; смена статуса; удаление заявки с полным стиранием ПДн; экспорт в CSV.
- Автоочистка: cron-скрипт удаляет заявки старше {{RETENTION_MONTHS|12}} месяцев — срок должен совпадать с указанным в Политике обработки ПДн.
- ПДн не передаются в URL (только POST) и не пишутся в логи в открытом виде.

## 6. Безопасность
- Принудительный HTTPS: редирект в .htaccess, заголовок HSTS.
- Заголовки: Content-Security-Policy (default-src 'self' плюс только домены из п. 2.1), X-Content-Type-Options: nosniff, Referrer-Policy: strict-origin-when-cross-origin, X-Frame-Options: DENY (при необходимости frame-src только для карт).
- Запрещены eval и динамическая конкатенация SQL. Вывод пользовательских данных — только через htmlspecialchars.
- Прямой доступ к data/, .env, *.db закрыт правилами .htaccess.

## 7. Доступность и качество (ориентир — WCAG 2.1 AA / ГОСТ Р 52872-2019)
- Контраст текста не ниже 4.5:1, видимое состояние фокуса, label у каждого поля, alt у всех изображений, aria-live для сообщений формы, полная навигация с клавиатуры, кликабельные зоны от 44 px.
- Производительность: главная страница без портфолио — не тяжелее ~1 МБ; lazy-loading изображений; WebP с fallback; аудио портфолио не автозагружается.

## 8. SEO
- Русские title и description на каждой странице, Open Graph, канонические URL, человекочитаемые адреса.
- JSON-LD schema.org LocalBusiness (или MusicVenue): название, адрес в Казани, geo-координаты, телефон, openingHours, priceRange.
- sitemap.xml, robots.txt, favicon. Заготовка мета-тега подтверждения для Яндекс.Вебмастера.

## 9. Рабочий процесс
- Перед крупной задачей — короткий план и список затрагиваемых файлов; жди подтверждения.
- Непонятно — спрашивай. Не выдумывай реквизиты, цены, названия услуг и тексты о студии — запрашивай их у владельца.
- Секреты только через .env; в коде и примерах — плейсхолдеры.
- Комментарии в коде и сообщения коммитов — на русском.
- После каждого этапа объясняй, как проверить локально (`php -S localhost:8000 -t public_html`) и что именно должно работать.
