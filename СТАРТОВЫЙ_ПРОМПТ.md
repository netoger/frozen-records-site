# Стартовый промпт для Claude Code — сайт студии звукозаписи

## Как использовать
1. Создайте папку проекта, например `studio-site/`, и положите в её корень файл **CLAUDE.md** из этого набора. Claude Code автоматически читает CLAUDE.md из корня проекта и следует его правилам.
2. Откройте терминал в этой папке и запустите `claude`.
3. Вставьте **Промпт №1** целиком и отвечайте на вопросы анкеты.
4. Дальше работайте по этапам, подтверждая планы. Промпты №2–№4 используйте, когда дойдёте до соответствующего шага.

Важно про секреты: пароль от панели хостинга, от Госуслуг и от почты в чат не вставляйте никогда. Токен Telegram-бота, ключи SmartCaptcha и пароль SMTP кладите сами в локальный файл `.env` по образцу `.env.example`, который создаст Claude.

## Промпт №1 — старт проекта

```text
Прочитай CLAUDE.md в корне проекта и коротко подтверди, что понял ограничения (особенно разделы 2.1–2.4). Мы создаём сайт студии звукозаписи в Казани строго по этим правилам.

Работаем поэтапно. После каждого этапа останавливайся и жди моего подтверждения.

ЭТАП 1 — Анкета. Задай мне одним списком вопросы, без которых нельзя начинать:
- точное название студии (кириллица/латиница; название — зарегистрированный товарный знак);
- реквизиты ООО для подвала: полное наименование, ОГРН, ИНН, юридический адрес;
- фактический адрес студии, часы работы, телефон и e-mail для заявок;
- ссылки на VK, Telegram, MAX (что есть);
- перечень услуг с ценами: запись, сведение, мастеринг, аранжировка, аренда, репетиции — что из этого есть;
- длительность стандартного слота записи и рабочий график для генерации слотов;
- на сколько дней вперёд открывать онлайн-запись;
- фирменные цвета и логотип (если нет — предложи 2–3 палитры под студийную эстетику);
- какие фото и аудио будут в портфолио и подтверждены ли права на них.

ЭТАП 2 — План. На основе ответов предложи: карту сайта (секции главной страницы и отдельные страницы), схему БД и API модуля записи, текстовый вайрфрейм главной, полный список файлов проекта. Дождись моего согласования.

ЭТАП 3 — Реализация. Собери проект по CLAUDE.md: главная страница, модуль записи со свободными слотами, админка, страницы privacy/consent/rules с черновиками текстов, cookie-баннер, локальные шрифты, SEO-разметка (JSON-LD LocalBusiness для Казани), sitemap и robots. Все ключи (SmartCaptcha, SMTP, Telegram-бот) вынеси в .env.example и для каждого напиши, где именно его получить.

ЭТАП 4 — Локальная проверка. Дай команду запуска локального сервера и чек-лист ручного теста: бронирование слота; блокировка отправки без чекбокса согласия; срабатывание honeypot; попытка повторной брони того же слота; лимит 3 заявки в час с одного IP; запись уведомления в лог, если почта/Telegram недоступны; корректное отображение на экране 360 px.

Начни с ЭТАПА 1.
```

## Промпт №2 — юридические черновики и данные для Роскомнадзора

Используйте после того, как сообщите Claude реквизиты ООО.

```text
Сгенерируй черновики privacy.html, consent.html и rules.html для нашего ООО с учётом действующей редакции 152-ФЗ (отдельный документ согласия, локализация данных в РФ, cookie и Яндекс.Метрика как обрабатываемые данные). Укажи: цели обработки (онлайн-запись на услуги студии, обратная связь), состав данных (имя, телефон, комментарий, cookie, данные Метрики), правовые основания, срок хранения 12 месяцев, порядок отзыва согласия и удаления данных, права субъекта, контакт для запросов.

В начало каждого файла добавь комментарий «ЧЕРНОВИК: ТРЕБУЕТ ПРОВЕРКИ ЮРИСТОМ» и отдельным списком выдай места, которые юрист должен проверить в первую очередь.

Дополнительно создай файл rkn-uvedomlenie.md — заготовку данных для заполнения уведомления об обработке персональных данных в Роскомнадзор (подаётся через Госуслуги): категории субъектов и данных, цели, перечень действий с данными, место хранения (дата-центр нашего хостинг-провайдера в РФ), принятые меры защиты, ответственный за обработку. Напомни мне списком, какие внутренние документы ООО нужно оформить (приказ о назначении ответственного, положение об обработке ПДн, сроки хранения и порядок уничтожения).
```

## Промпт №3 — деплой на хостинг

Используйте после покупки хостинга и домена. Подставьте свои значения в квадратных скобках.

```text
Хостинг куплен: [Timeweb / Beget], тариф [название], домен [домен.ru] привязан, SSL Let's Encrypt включён в панели. Есть SSH-доступ; подключение настроено по ключу, пароли в чат вставлять не буду.

Составь пошаговый план деплоя и затем выполняем его по шагам:
1) перенос файлов проекта на сервер (rsync или git), правильное размещение public_html, каталога data/ и .env вне webroot;
2) права на каталоги и файл БД;
3) .htaccess: принудительный HTTPS, заголовки безопасности из CLAUDE.md, запрет доступа к data/ и .env;
4) проверка отправки e-mail через SMTP хостинга на адрес заявок;
5) настройка cron-задачи автоочистки старых заявок;
6) финальная проверка: сайт открывается по https, форма записи работает, письмо приходит, Telegram-уведомление либо приходит, либо тихо логируется как недоставленное.

Команды, содержащие секреты, я выполняю сам — просто давай их с плейсхолдерами.
```

## Промпт №4 — предзапусковый аудит

```text
Проведи предзапусковый аудит проекта по CLAUDE.md и выдай отчёт двумя списками — «готово» и «требует действий владельца»:
1) поиск по всему коду запрещённых доменов (googleapis, gstatic, jsdelivr, unpkg, cdnjs, google-analytics, googletagmanager, recaptcha, facebook, instagram) — покажи результат поиска;
2) форма записи не отправляется без чекбокса согласия (проверь фронт и бэк);
3) Яндекс.Метрика не загружается до нажатия «Принять» в cookie-баннере;
4) JSON-LD валиден и содержит адрес в Казани;
5) заголовки безопасности и HTTPS-редирект на месте;
6) все плейсхолдеры реквизитов {{...}} заменены реальными данными;
7) в текстах нет превосходных степеней и упоминаний запрещённых соцсетей;
8) страницы privacy/consent/rules опубликованы и слинкованы из подвала и из формы.

Напомни мне в конце: уведомление в Роскомнадзор должно быть подано ДО того, как форма начнёт принимать заявки.
```
